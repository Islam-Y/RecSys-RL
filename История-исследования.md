# Журнал второго задания: последовательные рекомендации и RL

## 1. Постановка и продуктовая цель — 2026-10-13

Первое задание завершено в отдельном репозитории RecSys. Во втором исследуется GPT-2 для next-item prediction, reward model и последующее RL-дообучение. Положительный эффект RL не предполагается заранее.

Продуктовый ориентир, согласованный с пользователем: рекомендации должны нравиться, поддерживать продолжение взаимодействий и возвращение в сервис. Дослушивание, лайки/дизлайки и возвращаемость — доступные или потенциальные косвенные сигналы. Возвращение по историческим логам не доказывает причинного эффекта новой рекомендации.

Короткие треки могут быть подходящими рекомендациями. Предположение о «быстром дофамине» не исследуется: соответствующих измерений в данных нет. Для выявления искажения reward из-за длины запланированы анализ длительности рекомендаций и разрезы качества по группам длительности.

## 2. Протокол и реализация первого этапа — 2026-10-13

До обучения сохранены [протокол](experiments/baseline-protocol.md) и [конфигурация](configs/mvp.json). На локальной машине 16 ГиБ памяти, Apple Silicon; выбран небольшой GPT-2: 2 слоя, embeddings 128, 4 головы. Предварительный бюджет — 3 эпохи, batch 128. Это первый контроль без RL, не окончательный размер системы.

Написаны команды `prepare`, `status`, `baseline`: временное разбиение Yambda, train-каталог, последовательности, GPT-2 из Transformers со случайной инициализацией, обучение и оценки на validation. Вход содержит только события строго до T. Прослушивания в один квантованный timestamp образуют несколько возможных целей; ни одно из них не попадает в контекст этого запроса. Время трактуется как секунды, без ошибочного множителя 5.

Версии проверены через PyPI: PyTorch 2.14.1, Transformers 5.19.0, DuckDB 1.5.6, NumPy 2.5.4; выбраны актуальные стабильные версии с поддержкой Python 3.14/macOS arm64. На этапе подготовки нейросетевая часть ещё не запускалась. Во время первой установки зависимостей пользователь попросил остановиться перед запуском модели для перезагрузки Mac; установка была остановлена. Затем пользователь разрешил завершить всю подготовку, сохранив ограничение на непосредственный запуск модели.

## 3. Подготовка данных — 2026-10-13

Число уникальных целевых треков с учётом нескольких целей на запрос: 68 451 / 5 840 / 5 793. Из train исключены 112 запросов с историей менее 5 событий.

В контекстах train/validation 61.770% / 63.843% событий представлены как UNK; сжатие каталога ограничивает информацию о вкусах. Для будущего расширения потребуется отдельная конфигурация и сравнение, без переноса выводов MVP на весь каталог.

На train/validation проверены контрольные суммы и условие `history_max_timestamp < target_timestamp`. Синтаксис исходников и CLI справка обработаны успешно. Метрики рекомендаций не рассчитывались; test сформирован для будущей итоговой оценки.

## 5. Первое обучение GPT-2 — 2026-10-13

Пользователь отдельно разрешил запуск модели. Выполнена команда `.venv/bin/python -m recsys_rl baseline --device auto`; внешнее измерение `/usr/bin/time -l` и вывод сохранены в `outputs/baseline-v1.log`. Исходный код — коммит `6f276bcbe337e2d50c07c04721fb2de087bab985`. Протокол, конфигурация и подготовленные выборки не менялись.

Apple M4, MPS, 661 504 параметра. Все 3 эпохи завершены без ошибки; выполнено 1 404 обучающих шага. Train loss по эпохам: 7.30754 / 6.79535 / 6.48020. Validation NDCG@10: 0.04294 / 0.05799 / 0.06786. Лучший checkpoint — эпоха 3.

| Вариант | NDCG@10 | Recall@10 |
|---|---:|---:|
| Популярность на train | 0.01427 | 0.03228 |
| GPT-2 | 0.06786 | 0.11425 |
| Недавние треки + популярность | 0.10776 | 0.16142 |

Сравнение использует одинаковые 5 000 validation-запросов от 734 пользователей. Модель превосходит глобальную популярность, но уступает простому персональному контролю по недавним трекам. Это ограничение текущего baseline, а не основание исключать сильный контроль из будущего сравнения с RL.

Полный процесс занял 81.54 с; цикл обучения/validation/сохранения — 75.56 с. Время эпох: 28.18 / 23.65 / 23.57 с. Предварительная оценка 10–30 минут до первого запуска оказалась завышенной для этого небольшого MVP. По ходу первой эпохи она была уточнена. macOS сообщил максимум RSS 596.61 МиБ и peak memory footprint 1.587 ГиБ; полный пик выделений MPS отдельно не измерялся.

Поведение GPT-2 @10: охват каталога 54.75%, доля десяти наиболее выдаваемых объектов 11.546%, доля повторов из контекста 17.73%, средняя длительность 188.06 с. Разрезы по длительности и все @5/10/20 сохранены в [агрегированном результате](experiments/baseline-result.json). Интерпретация — в [решении](Решение.md).

Checkpoint и ranking-списки validation сохранены локально. Пересчёт метрик по сохранённым спискам, повторное построение обоих контролей, проверка SHA-256 модели, конфигурации, протокола и неизменности test-файла прошли успешно. Test-метрики не рассчитывались. Один seed и validation, использованный для выбора checkpoint, не дают независимого подтверждения качества. Reward model, RL и влияние на удовлетворённость/возвращение ещё не исследованы.

## 6. План проверки размера модели — 2026-10-13

После короткого первого запуска пользователь предложил усилить модель. Выбрана GPT-2 с 6 слоями, размером представления 384 и 6 головами внимания. Подготовлен [отдельный протокол](experiments/baseline-capacity-protocol.md), зафиксированный до новых обучений.

Для отделения эффекта размера от числа эпох добавлен контроль: исходная архитектура 2/128/4 обучается с тем же новым бюджетом. Обе модели стартуют с нуля, максимум 15 эпох; остановка после трёх эпох без улучшения validation NDCG@10. Seed, оптимизатор, learning rate, batch, dropout и метрики одинаковы. Предыдущий checkpoint не содержит состояния оптимизатора, поэтому его нельзя точно продолжить как исходное обучение.

Повторно используются прежние train/validation, каталог и контексты. Проверка совместимости отделена от полного хеша конфигурации: для данных должны совпасть раздел `data` и seed подготовки, а настройки конкретного обучения сохраняются и хешируются отдельно. Добавлен параметр CLI `--protocol` для протокола нового запуска. Первый отчёт, конфигурация MVP и исходные данные сохраняются.

Расширение каталога отложено: оно изменит доступную информацию и состав целевых запросов, поэтому требует отдельного сравнения. [HSTU](https://arxiv.org/abs/2402.17152), [Sona](https://arxiv.org/abs/2608.11015) и [GPTRec](https://arxiv.org/abs/2403.04875) рассмотрены как ориентиры; основная модель остаётся GPT-2 по условию задания. Финальный test не используется для выбора размера или эпохи.

## 7. Результат сравнения размеров и бюджета обучения — 2026-10-13

Выполнены два последовательных запуска на Apple M4/MPS по заранее сохранённому протоколу. Исходный код и настройки — коммит `3e60e47b9f0e47d0fb8a8ddb854123754709c4be`. Сначала обучена большая модель, затем маленький контроль; одновременного обучения на MPS не было. Данные повторно не готовились.

Большая GPT-2: 11 441 664 параметра, 6 слоёв, размер 384, 6 голов. Завершено 13 эпох и 6 084 шага. Лучший NDCG@10 = 0.068086 на эпохе 10; эпохи 11–13 не превысили максимум, сработал early stopping. Полный процесс — 3 335.01 с, или 55.58 минуты. Peak memory footprint по macOS — 3.73 ГиБ.

Маленький контроль: 661 504 параметра, 2 слоя, размер 128, 4 головы. Завершены все 15 эпох и 7 020 шагов. Выбран checkpoint эпохи 14: NDCG@10 = 0.090218, Recall@10 = 0.138909. На пятнадцатой эпохе NDCG@10 снизился до 0.089081. Полный процесс — 364.70 с, или 6.08 минуты; peak memory footprint — 1.59 ГиБ. Это показатели учёта памяти процесса, не полного пика MPS или системы.

| Вариант | NDCG@10 | Recall@10 |
|---|---:|---:|
| Первый MVP, 3 эпохи | 0.06786 | 0.11425 |
| Маленькая модель, выбранная эпоха 14 | 0.09022 | 0.13891 |
| Большая модель, выбранная эпоха 10 | 0.06809 | 0.11271 |
| Недавние треки + популярность | 0.10776 | 0.16142 |

NDCG первых трёх эпох маленького контроля точно совпал с первым запуском; различия train loss находятся на уровне округления вычислений. Более долгое обучение увеличило NDCG@10 относительно MVP на 0.02236, или 32.96%, и Recall@10 на 21.58%. Это прирост выбранных офлайн-метрик; пользовательский эффект не оценивался.

Большая модель уступила маленькому контролю по всем шести Recall/NDCG @5/10/20, имея в 17.30 раза больше параметров и потребовав в 9.14 раза больше времени. Сравнение при равных трёх эпохах также в пользу маленькой: NDCG@10 0.06786 против 0.03999. Итог относится к данному рецепту обучения: learning rate не подбирался отдельно, глубина, ширина и число голов менялись совместно, а одинаковый предел эпох не означает одинаковые вычислительные затраты.

У выбранного маленького checkpoint охват каталога @10 — 97.55%, концентрация десяти наиболее выдаваемых объектов — 6.74%, повторы из контекста — 21.82%, средняя длительность — 192.65 с. У большого: 83.30% / 9.14% / 14.87% / 190.90 с. Диагностики помогают описать поведение, но не доказывают удовлетворённость пользователя. Контроль по недавним трекам всё ещё выше маленькой модели на 0.01754 NDCG@10.

Для следующего этапа среди обученных GPT-2 выбран локальный checkpoint `outputs/baseline-capacity-small-v1/baseline.pt`, эпоха 14. Большой вариант и первый MVP сохранены для истории; увеличивать размер на основании этого эксперимента не оправдано. Reward model и RL пока не обучались.

Метрики пересчитаны по сохранённым ranking-спискам обоих запусков; пользователи, timestamps и множества целей совпали с validation. Контроли совпали с первым отчётом. Проверены SHA-256 сырых данных, каталога, train/validation/test, моделей, конфигураций и протокола. Исторические конфигурация MVP, протокол, отчёт готовности и первый результат совпадают с сохранённой версией Git. Test проверен только по контрольной сумме, без расчёта метрик. [Агрегированный отчёт](experiments/baseline-capacity-result.json) содержит обе кривые обучения, все метрики, диагностики и контрольные суммы.
