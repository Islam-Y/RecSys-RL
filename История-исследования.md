# Журнал второго задания: последовательные рекомендации и RL

## 1. Постановка и продуктовая цель — 2026-10-13

Первое задание завершено в отдельном репозитории RecSys. Во втором исследуется GPT-2 для next-item prediction, reward model и последующее RL-дообучение. Положительный эффект RL не предполагается заранее.

Продуктовый ориентир, согласованный с пользователем: рекомендации должны нравиться, поддерживать продолжение взаимодействий и возвращение в сервис. Дослушивание, лайки/дизлайки и возвращаемость — доступные или потенциальные косвенные сигналы. Возвращение по историческим логам не доказывает причинного эффекта новой рекомендации.

Короткие треки могут быть подходящими рекомендациями. Предположение о «быстром дофамине» не исследуется: соответствующих измерений в данных нет. Для выявления искажения reward из-за длины запланированы анализ длительности рекомендаций и разрезы качества по группам длительности.

## 2. Протокол и реализация первого этапа — 2026-10-13

До обучения сохранены [протокол](experiments/baseline-protocol.md) и [конфигурация](configs/mvp.json). На локальной машине 16 ГиБ памяти, Apple Silicon; выбран небольшой GPT-2: 2 слоя, embeddings 128, 4 головы. Предварительный бюджет — 3 эпохи, batch 128. Это первый контроль без RL, не окончательный размер системы.

Написаны команды `prepare`, `status`, `baseline`: временное разбиение Yambda, train-каталог, последовательности, GPT-2 из Transformers со случайной инициализацией, обучение и оценки на validation. Вход содержит только события строго до T. Прослушивания в один квантованный timestamp образуют несколько возможных целей; ни одно из них не попадает в контекст этого запроса. Время трактуется как секунды, без ошибочного множителя 5.

Версии проверены через PyPI: PyTorch 2.14.1, Transformers 5.19.0, DuckDB 1.5.6, NumPy 2.5.4; выбраны актуальные стабильные версии с поддержкой Python 3.14/macOS arm64. Нейросетевая часть пока не запускалась. Во время первой установки зависимостей пользователь попросил остановиться перед запуском модели для перезагрузки Mac; установка была остановлена. Затем пользователь разрешил завершить всю подготовку, сохранив ограничение на непосредственный запуск модели.

## 3. Подготовка данных — 2026-10-13

Исходный файл скопирован из первого проекта в локальный `data/raw/` второго проекта. SHA-256: `b92f6c97277a554c8a7d6cfea900eca51639fd53a3e6c4fa58b82e35fd35804d`.

В исходном файле 46 467 212 событий `listen` от 9 238 пользователей по 877 168 объектам; эти числа относятся к прослушиваниям, а не ко всем типам событий Yambda. Глобальные 70-й и 85-й процентили timestamp — `19983235` и `23121935` секунд. Данные заканчиваются на `26000000`.

По train-периоду выбраны 1 000 пользователей и 2 000 треков; локальная история содержит 6 020 268 прослушиваний. Подготовлены 59 888 train-запросов, 5 000 validation и 5 000 test. Число уникальных целевых треков с учётом нескольких целей на запрос: 68 451 / 5 840 / 5 793. Из train исключены 112 запросов с историей менее 5 событий.

Каталог покрывает 25.904% исходных прослушиваний выбранных пользователей в train, 23.790% в validation и 19.871% в test. Оценка будет условной на попадание цели в этот каталог. В контекстах train/validation 61.770% / 63.843% событий представлены как UNK; сжатие каталога ограничивает информацию о вкусах. Для будущего расширения потребуется отдельная конфигурация и сравнение, без переноса выводов MVP на весь каталог.

На train/validation проверены контрольные суммы и условие `history_max_timestamp < target_timestamp`. Синтаксис исходников и CLI справка обработаны успешно. Метрики рекомендаций не рассчитывались; test сформирован для будущей итоговой оценки.

## 4. Готовность к запуску — 2026-10-13

Установка зависимостей завершена. `pip check` сообщил `No broken requirements found`; установленное окружение сохранено в `requirements-lock.txt`. Команда `status` проверила конфигурацию и протокол по SHA-256, каталог и три файла выборок, формы и диапазоны токенов train/validation, отсутствие повторяющихся query ID и соблюдение временных границ.

Классы `GPT2Config` и `GPT2LMHeadModel` импортируются. PyTorch сообщает доступность MPS на Apple Silicon. Экземпляр GPT-2 не создавался; forward, backward и обучение не выполнялись. Совместимость вычислений модели и фактическая память остаются непроверенными до непосредственного запуска. [Отчёт готовности](experiments/preparation-result.json) сохраняет эти ограничения и состояние `prepared_awaiting_model_start`.

Добавлены правила `tmp/` и `.cache/` в `.gitignore`. Датасет, подготовленные массивы и окружение остаются локальными; в Git сохраняются код, настройки, протокол, версии зависимостей и агрегированные числа подготовки.
