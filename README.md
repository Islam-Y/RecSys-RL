## Текущий статус

Сравнены три размера GPT-2 и восемь рецептов обучения маленькой модели. Уменьшение learning rate с 0.0005 до 0.0001 повысило NDCG@10 на каждом из training seeds 42, 43, 44. Средний NDCG@10 вырос с 0.09026 до 0.10308 (+14.21%), Recall@10 — с 0.13858 до 0.15571 (+12.35%).

Для следующего этапа выбран checkpoint с seed 42, эпоха 26: NDCG@10 = 0.10275, Recall@10 = 0.15215. Архитектура сохраняет 661 504 параметра. Контроль по недавним трекам всё ещё выше по качеству. Финальный test не оценивался; reward model и RL-дообучение ещё не реализованы.

Продуктовая цель — удовлетворённость пользователя, продолжение взаимодействий и возвращение в сервис. Дослушивание и возвращаемость рассматриваются как косвенные сигналы; рост прогноза reward model сам по себе не доказывает пользу пользователю.

## Подготовка окружения и данных

Локально используется Python 3.14.7. Зафиксированы актуальные стабильные версии: [PyTorch 2.14.1](https://pypi.org/project/torch/2.14.1/), [Transformers 5.19.0](https://pypi.org/project/transformers/5.19.0/), [DuckDB 1.5.6](https://pypi.org/project/duckdb/1.5.6/), [NumPy 2.5.4](https://pypi.org/project/numpy/2.5.4/). Для выбранного NumPy нужен Python 3.12 или новее.

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
mkdir -p data/raw
curl -L --fail --output data/raw/yambda-50m-multi_event.parquet https://huggingface.co/datasets/yandex/yambda/resolve/main/flat/50m/multi_event.parquet
python -m recsys_rl prepare data/raw/yambda-50m-multi_event.parquet
```

Команда подготовки откажется перезаписывать непустой каталог. Для другого запуска задайте `--output-dir` и при необходимости `--config`.

## Подготовленные выборки

Источник — [Yambda-50M](https://huggingface.co/datasets/yandex/yambda), 46 467 212 событий `listen`. Выбраны 1 000 пользователей по их train-истории и каталог из 2 000 наиболее частых train-треков. Вход — BOS и до 64 предыдущих прослушиваний, минимальная история — 5 событий.

| Период | Запросов | Пользователей в запросах | Целевых треков | Покрытие событий каталогом |
|---|---:|---:|---:|---:|
| Train | 59 888 | 961 | 68 451 | 25.90% |
| Validation | 5 000 | 734 | 5 840 | 23.79% |
| Test | 5 000 | 755 | 5 793 | 19.87% |

Глобальные временные границы: train до `19983235` секунд включительно, validation до `23121935`, test до `26000000`. Test-файл сформирован и имеет контрольную сумму; метрики на нём не рассчитывались.

Контекст использует только события строго раньше T. При нескольких прослушиваниях в один timestamp они образуют множество целей и все исключаются из контекста текущего запроса. Поэтому число целевых треков больше числа запросов. 112 выбранных train-запросов исключены из-за недостаточной истории.

**Граница оценки:** метрики условны на попадание цели в ограниченный каталог. Ранжируются все 2 000 объектов без сэмплирования негативов. Такая оценка не описывает качество на полном каталоге Yambda или онлайн-эффект. Объекты вне каталога сохраняются в истории как UNK: это 61.77% событий в train-контекстах.

## Проверка готовности без запуска модели

```bash
python -m recsys_rl status --output experiments/preparation-result.json
```

Команда проверяет контрольные суммы, временные границы, формы массивов, токены, импорт классов GPT-2 и доступность MPS/CUDA. Она не создаёт экземпляр модели и не выполняет обучение. Это проверка окружения и данных; выполненные обучения описаны в отдельных отчётах.

`preparation-result.json` сохранён как снимок подготовки до первого обучения: его флаги запуска равны `false`. Фактический успешный forward/backward и обучение отражены в `baseline-result.json`. `pip check` не обнаружил конфликтов зависимостей.

## Отдельный запуск базовой модели

Команда первого обучения:

```bash
python -m recsys_rl baseline --device auto
```

Конфигурация: GPT-2 со случайной инициализацией, 2 decoder-блока, размер embeddings 128, 4 головы, 3 эпохи, batch 128. Токены — ID треков; текстовые веса и токенизатор не используются. На Apple Silicon `auto` выбирает MPS при его доступности.

Лучший checkpoint выбирается по validation NDCG@10. Контроли — train-популярность и последние уникальные треки из доступной истории; недостающие места заполняются train-популярностью. Сохраняются Recall/NDCG @5/10/20, концентрация рекомендаций, повторы и длительность. Результаты сохранены в `outputs/baseline-v1/`, лог процесса — в `outputs/baseline-v1.log`. Непустой каталог не перезаписывается; для повтора задайте новый `--output-dir`, например `outputs/baseline-repeat`.

## Первые результаты — validation

Лучший checkpoint — эпоха 3. Все варианты оценены на одних 5 000 запросах от 734 пользователей, по всему ограниченному каталогу из 2 000 треков.

| Вариант | NDCG@10 | Recall@10 |
|---|---:|---:|
| Популярность на train | 0.01427 | 0.03228 |
| GPT-2 | 0.06786 | 0.11425 |
| Недавние треки + популярность | **0.10776** | **0.16142** |

Train loss снизился с 7.3075 до 6.4802, validation NDCG@10 выросла с 0.04294 после первой эпохи до 0.06786 после третьей. Пайплайн работает и модель обучается, но текущий небольшой baseline слабее простого персонального контроля. Эта проверка использовалась для выбора checkpoint; статистическая значимость и финальный test ещё не оценены.

Полный процесс занял 81.54 с, цикл трёх эпох с validation и сохранением — 75.56 с. Это измерение одного небольшого запуска, а не оценка времени обучения полного GPT-2 на всём Yambda. Подробные метрики, разрезы по длительности и контрольные суммы — в [JSON](experiments/baseline-result.json), интерпретация — в [решении](Решение.md).

## Проверка размера модели и бюджета обучения

Сначала по [протоколу двух размеров](experiments/baseline-capacity-protocol.md) обучены маленький и большой варианты. 14 октября добавлена промежуточная модель по [отдельному протоколу](experiments/baseline-medium-protocol.md). Все три варианта сравнения обучены с нуля на прежних train/validation и каталоге: максимум 15 эпох, одинаковые seed 42, AdamW и early stopping после трёх эпох без улучшения NDCG@10.

| Вариант | Параметры | Лучшая / завершено эпох | NDCG@10 | Recall@10 | Полный запуск |
|---|---:|---:|---:|---:|---:|
| Первый MVP, 2 слоя / 128 | 661 504 | 3 / 3 | 0.06786 | 0.11425 | 81.54 с |
| Маленькая, 2 слоя / 128, дольше | 661 504 | 14 / 15 | 0.09022 | 0.13891 | 364.70 с |
| Промежуточная, 4 слоя / 256 | 3 688 960 | 8 / 11 | 0.06992 | 0.11414 | 1 107.41 с |
| Большая, 6 слоёв / 384 | 11 441 664 | 10 / 13 | 0.06809 | 0.11271 | 3 335.01 с |
| Недавние треки + популярность | — | — | **0.10776** | **0.16142** | — |

Более долгое обучение маленькой модели дало **+0.02236 NDCG@10, или +32.96% относительно первого MVP**, и +21.58% Recall@10. NDCG первых трёх эпох контрольного запуска совпал с исходным. Прирост относится к офлайн-метрикам, не к удовлетворённости или возвращаемости пользователей.

Большая модель содержит в 17.30 раза больше параметров и потребовала в 9.14 раза больше времени, чем новый маленький вариант, но уступила ему по всем шести Recall/NDCG @5/10/20. Все три варианта имеют одинаковый максимальный бюджет эпох и правило остановки; число завершённых эпох и затраты вычислений различаются. Оптимизатор отдельно под архитектуры не подбирался, поэтому вывод относится к этому рецепту обучения.

Промежуточная GPT-2 остановилась после 11 эпох; выбран checkpoint эпохи 8. Она немного выше большой модели по NDCG@10 (+2.69%), но ниже маленькой на 0.02030, или 22.50%. Recall@10 ниже маленькой на 17.83%; полный процесс занял в 3.04 раза больше времени. Промежуточный размер в этом эксперименте не улучшил выбранный baseline.

На этапе сравнения размеров выбран `outputs/baseline-capacity-small-v1/baseline.pt`, эпоха 14. Его охват каталога @10 — 97.55%, концентрация десяти наиболее выдаваемых треков — 6.74%, повторы из контекста — 21.82%. Контроль по недавним трекам сохраняется: его NDCG@10 выше на 0.01754. Затем рецепт маленькой модели уточнён в следующем эксперименте.

Один seed, последовательный выбор конфигураций и checkpoint по одной validation, test без оценки. Сохранённые ranking-списки пересчитаны; контроли, исходные данные и исторические отчёты не изменились. Кривые, разрезы и контрольные суммы — в отчётах [первых двух вариантов](experiments/baseline-capacity-result.json) и [промежуточной модели](experiments/baseline-medium-result.json).

## Подбор настроек маленькой GPT-2

По [протоколу](experiments/small-tuning-protocol.md) проверены восемь рецептов: контроль, три learning rate, два dropout и два weight decay. Каждый вариант меняет один параметр относительно контроля; максимум — 30 эпох, остановка после пяти эпох без улучшения NDCG@10. Лучший кандидат на seed 42 — `lr-low`: learning rate 0.0001, dropout 0.1, weight decay 0.01. Он и контроль дополнительно обучены с seeds 43 и 44; всего выполнено 12 запусков.

Среднее ± выборочное стандартное отклонение по трём training seeds, на прежних 5 000 validation-запросах:

| Рецепт | NDCG@10 | Recall@10 |
|---|---:|---:|
| Контроль, learning rate 0.0005 | 0.09026 ± 0.00019 | 0.13858 ± 0.00216 |
| Выбранный, learning rate 0.0001 | **0.10308 ± 0.00034** | **0.15571 ± 0.00361** |
| Недавние треки + популярность, без обучения | 0.10776 | 0.16142 |

NDCG@10 вырос на 13.89% / 14.33% / 14.40% для seeds 42 / 43 / 44. Кандидат выполнил заранее заданное правило замены контроля: выиграть на каждом seed. Все шесть Recall/NDCG @5/10/20 также выше контроля на каждом seed. Увеличение бюджета исходного рецепта с 15 до 30 эпох само по себе не изменило выбранный результат seed 42: сохранилась эпоха 14, остановка на эпохе 19.

В качестве исходной политики для RL зафиксирован `outputs/small-tuning-v1/runs/lr-low/seed-42/baseline.pt`, эпоха 26; лучший seed отдельно не выбирался. Этот запуск завершил 30 эпох за 848.57 с против 19 эпох за 521.43 с у контроля. Архитектура и число параметров одинаковы; задержка инференса не измерялась. Охват каталога выбранного checkpoint — 93.85%, концентрация — 7.34%, повторы из контекста — 27.80%, средняя длительность — 191.00 с. По сравнению с контролем seed 42 охват снизился, а концентрация и повторы выросли.

Три seeds описывают случайность обучения на одних данных. Подбор и выбор checkpoint используют ту же validation; стандартное отклонение не является доверительным интервалом. Сочетания настроек не перебирались. Прирост относится к офлайн-метрикам ограниченного каталога. Все ranking-метрики пересчитаны, данные и test-файл сохранили контрольные суммы. Полные кривые, диагностики и время каждого запуска — в [результате](experiments/small-tuning-result.json), таблица восьми рецептов — в [решении](Решение.md).

Воспроизведение серии в новом каталоге:

```bash
python -m recsys_rl tune --device auto --output-dir outputs/small-tuning-repeat
```

Для продолжения исходной серии используется `python -m recsys_rl tune --device auto --resume`: завершённые запуски повторно сверяются, частично обученные модели внутри запуска не продолжаются. Отдельное обучение выбранного рецепта:

```bash
python -m recsys_rl baseline --config configs/baseline-selected.json --protocol experiments/small-tuning-protocol.md --output-dir outputs/baseline-selected-repeat --device auto
```

## Следующие этапы
