# Проверка размера GPT-2 и бюджета обучения

Зафиксировано 2026-10-13 до новых обучений. Первый трёхэпоховый запуск сохраняется как исторический результат; его настройки, данные и отчёт не перезаписываются.

## Вопрос

Улучшает ли увеличение GPT-2 качество next-item prediction на текущей выборке? Отдельный контроль с более долгим обучением маленькой модели нужен, чтобы не приписать большему размеру эффект дополнительных эпох.

## Сравниваемые варианты

| Вариант | Слои | Размер представления | Головы | Максимум эпох |
|---|---:|---:|---:|---:|
| Первый MVP, исторический результат | 2 | 128 | 4 | 3 |
| Маленькая модель, дольше | 2 | 128 | 4 | 15 |
| Большая модель | 6 | 384 | 6 | 15 |

Новые конфигурации: [маленькая](../configs/baseline-small-long.json), [большая](../configs/baseline-large.json). Обе обучаются с нуля: исходный checkpoint не содержит состояния оптимизатора для точного продолжения обучения.

## Что фиксируется

- Повторно используются те же файлы `data/processed/mvp/`: train 59 888 запросов, validation 5 000, каталог 2 000 треков, контекст до 64 событий. Правила подготовки и временные границы — из [первого протокола](baseline-protocol.md).
- Seed 42; AdamW, learning rate 0.0005, weight decay 0.01, batch 128, gradient clip 1.0, dropout 0.1. Планировщик learning rate и подбор гиперпараметров не добавляются.
- Для обеих новых моделей максимум 15 эпох и early stopping после трёх подряд эпох без строго большего validation NDCG@10. Выбирается checkpoint с наибольшим NDCG@10; при равенстве остаётся более ранний.
- Все варианты ранжируют тот же полный ограниченный каталог. Контроли — train-популярность и недавние уникальные треки с заполнением популярностью.
- Итоговые Recall/NDCG @5/10/20, охват, концентрация, повторы и длительность считаются одним кодом. Сохраняются также кривые по всем завершённым эпохам, размер модели и время.
- Сравнение результатов после трёх эпох показывает поведение при одинаковом числе шагов. Сравнение лучших checkpoint показывает результат при одинаковом максимальном бюджете эпох и правиле остановки. Вычислительные затраты при этом различаются.
- Изменения размера, глубины и числа голов оцениваются совместно; этот запуск не изолирует каждую настройку архитектуры. Вывод относится к фиксированному рецепту обучения, а не к максимально настроенным моделям.
- Данные и sampling seed проверяются по содержимому настроек подготовки; конфигурация конкретного обучения хешируется отдельно. SHA-256 train/validation и каталога проверяются перед использованием. Настройки модели и число эпох не требуют повторной подготовки данных.
- Финальный test не оценивается. Расширение каталога и выборки, reward model и RL не входят в этот запуск.

## Интерпретация

Первичная метрика — validation NDCG@10, Recall@10 — дополнительная. Сравнивать большую модель нужно прежде всего с маленькой, обучавшейся дольше, и с контролем по недавним трекам. Разница с историческим MVP сама по себе не доказывает преимущество большей архитектуры.

Один seed и validation, использованный для выбора эпохи, не подтверждают статистическую устойчивость или пользу пользователям. Больший размер не считается успехом сам по себе. Потеря истории через UNK и условная оценка на популярном подкаталоге сохраняются.

## Воспроизведение

После подготовки данных исходной конфигурацией MVP выполнить последовательно:

```bash
python -m recsys_rl baseline --config configs/baseline-large.json --protocol experiments/baseline-capacity-protocol.md --output-dir outputs/baseline-capacity-large-v1 --device auto
python -m recsys_rl baseline --config configs/baseline-small-long.json --protocol experiments/baseline-capacity-protocol.md --output-dir outputs/baseline-capacity-small-v1 --device auto
```

Непустые каталоги результатов не перезаписываются. На локальной машине запуски выполняются последовательно, чтобы не конкурировать за MPS и память.
