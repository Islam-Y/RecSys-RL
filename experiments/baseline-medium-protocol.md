# Проверка промежуточного размера GPT-2

Зафиксировано 2026-10-14 до обучения промежуточной модели. Конфигурация выбрана после сравнения маленькой и большой моделей; этот запуск дополняет предыдущий эксперимент, а его протокол и результаты сохраняются.

## Гипотеза

GPT-2 из 4 слоёв, с размером представления 256 и 4 головами внимания может дать лучший баланс качества и затрат, чем проверенные варианты 2/128/4 и 6/384/6. При каталоге 2 000 треков ожидается 3 688 960 параметров; фактическое число фиксируется при запуске.

Ориентир для сравнения — маленькая модель после более долгого обучения: validation NDCG@10 = 0.09021753745820965, Recall@10 = 0.13890882617382616. Первый трёхэпоховый MVP не является главным соперником. Сильный контроль по недавним трекам сохраняется: NDCG@10 = 0.10775509399008554.

## Неизменные условия

- Те же подготовленные файлы `data/processed/mvp/`: 59 888 train-запросов, 5 000 validation, каталог 2 000 треков, история до 64 событий. Подготовка описана в [первом протоколе](baseline-protocol.md).
- Обучение с нуля, seed 42. AdamW, learning rate 0.0005, weight decay 0.01, batch 128, gradient clip 1.0, dropout 0.1; планировщик learning rate и дополнительный подбор настроек отсутствуют.
- Максимум 15 эпох; остановка после трёх последовательных эпох без строго большего validation NDCG@10. Выбирается лучший checkpoint; при равенстве сохраняется более ранний.
- Полный ограниченный каталог без сэмплирования негативов, те же Recall/NDCG @5/10/20 и правила обработки нескольких целей на timestamp.
- Те же диагностики: охват каталога, концентрация, повторы из доступного контекста, средняя длительность и разрезы по длительности целей.
- Контроли — train-популярность и недавние уникальные треки с заполнением популярностью. Их значения должны совпасть с [предыдущим отчётом](baseline-capacity-result.json).
- Код обучения, зависимости, данные, каталог и ограничения UNK сохраняются. Финальный test не оценивается; проверяется только его контрольная сумма.

## Сравнение и границы вывода

Первичная метрика — NDCG@10, дополнительная — Recall@10. Сравниваются лучшие checkpoint при одинаковом максимуме эпох и правиле остановки; фактические эпохи, число шагов и вычислительные затраты могут отличаться. Дополнительно сравнивается качество после первых трёх эпох при одинаковом числе шагов.

Фиксируются абсолютные и относительные изменения метрик, число параметров, время процесса и диагностики поведения. При отсутствии прироста основной метрики исходным вариантом для следующего этапа остаётся маленькая GPT-2. При приросте отдельно оцениваются его величина и затраты; постоянное предпочтение промежуточной архитектуры заранее не предполагается.

Конфигурации выбираются последовательно с использованием одной validation-выборки. Оценка остаётся исследовательской: один seed, выбор эпохи по validation, без независимого test и доверительных интервалов. Настройки оптимизатора отдельно под архитектуры не подбираются. Размер модели сам по себе не доказывает качество, а офлайн-метрики не измеряют удовлетворённость или возвращаемость.

## Воспроизведение

После исходной подготовки данных:

```bash
python -m recsys_rl baseline --config configs/baseline-medium.json --protocol experiments/baseline-medium-protocol.md --output-dir outputs/baseline-capacity-medium-v1 --device auto
```

Непустой каталог результатов не перезаписывается. Сохраняются checkpoint, ranking-списки validation, история всех эпох и сводка; лог и `/usr/bin/time -l` используются для измерения полного процесса. Reward model, RL, расширение каталога и выборки в этот запуск не входят.
