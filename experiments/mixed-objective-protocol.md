# Смешанная цель RL и next-item - 2026-10-15

Расширение завершённой первой серии, без изменения её отчётов. План записан до подготовки нового holdout и новых обучений. Основная гипотеза: добавление next-item loss к точному ожидаемому reward и KL уменьшит потерю релевантности при повышении reward.

## Метод и фиксированный бюджет

`L = -w_reward*E_pi[p(h,i)] + beta*KL(pi||pi_ref) + gamma*CE_next_item`.

Для нескольких целей одного user/T CE - среднее отрицательное log probability по уникальным наблюдавшимся целям, затем среднее по запросам. Reward model и reference заморожены. Все варианты начинаются с одного baseline seed 42, эпоха 26. Используются ровно те же 4 000 поздних policy train контекстов и reward-кэш первого пилота; теперь реальные next-item цели входят в supervised-часть loss. Метки доли прослушивания в loss не добавляются.

Все варианты: пять эпох, AdamW learning rate 0.00005, batch 64, weight decay 0, clip norm 1, dropout выключен. Выбирается последняя эпоха без validation early stopping. Reward raw, reference, калибровка и D95 = 285 секунд не меняются.

| Вариант | w_reward | beta | gamma |
|---|---:|---:|---:|
| rl-only | 1 | 0.1 | 0 |
| strong-kl | 1 | 1 | 0 |
| next-item-only | 0 | 0 | 1 |
| mixed-001 | 1 | 0.1 | 0.001 |
| mixed-01 | 1 | 0.1 | 0.01 |
| mixed-1 | 1 | 0.1 | 0.1 |

Контроль next-item-only отделяет эффект RL от дополнительного supervised-обучения. Все шесть вариантов обучаются заново seed 42. Выбранный смешанный кандидат и next-item-only дополнительно обучаются seeds 43/44; максимум десять обучений. Различается порядок батчей, исходный checkpoint остаётся одним.

Мотивация смешанной цели - сохранение исходной способности модели; аналогичное смешивание исследовалось для языковых моделей в [Ouyang et al., PPO-ptx](https://arxiv.org/html/2203.02155v1). Перенос пользы в рекомендации является нашей проверяемой гипотезой, а не установленным результатом статьи.

## Отбор на прежней validation

Прежние 5 000 validation-запросов уже использованы адаптивно; они служат для разработки, не для независимого подтверждения. Старый final test повторно не оценивается.

Смешанный кандидат допускается, если:

- NDCG@10 >= 99% максимума baseline и next-item-only того же seed.
- Hybrid top-10 reward выше baseline, strong-kl seed 42 и next-item-only того же seed.
- Охват каталога >= 95% baseline; концентрация десяти самых выдаваемых треков <= 125% baseline.
- На seed-42 sampled-rollout пятого шага повтор предыдущего объекта <= baseline + 0.03, среднее число уникальных треков в пятёрке >= baseline - 0.15.

Из допустимых выбирается максимальный hybrid reward, при равенстве - порядок конфигурации. Кандидат принимается только при выполнении ranking/reward/охват/концентрация критериев на всех трёх seeds. Rollout-ограничения проверяются для checkpoint seed 42. Если кандидата нет или подтверждение не прошло, сохраняется baseline; новые варианты вне плана не добавляются.

Сохраняются все Recall/NDCG @5/10/20, три reward top-10, expected reward softmax, KL/энтропия, длительность, поддержка объектов и разрезы. Для baseline и шести seed-42 вариантов выполняются 14 greedy/sampled-rollout на прежних 1 000 validation-историях с теми же общими случайными числами. Синтетическое прослушивание не является реальным откликом.

## Новый holdout по пользователям

До запусков выбираются 1 000 пользователей Yambda, не входивших в **полную** первоначальную популяцию 1 000 пользователей, включая тех, у кого не было train-запросов. Исключение строится по уникальным user ID исходного `listen-events.parquet`. Требуется >= 50 событий listen до исходной train-границы; выбор по DuckDB hash(user, 20261015), затем user ID. Будущие reward-метки при выборе не используются.

Каталог сохраняется исходным: 2 000 объектов с теми же токенами/длительностями. Из периода `23121935 < T <= 26000000` выбираются до 5 000 запросов по hash(user,T,20261015), история BOS + последние 64 события строго раньше T; минимум 5 событий. Текущие user/T события исключаются из истории. При подготовке читаются только ID, timestamps и event_type, без played_ratio_pct. Истории и target ID запечатываются в отдельном NPZ с SHA-256; до завершения выбора они не используются для inference или оценки.

Этот holdout проверяет перенос на ранее не использованных пользователей в том же датасете/периоде. Все пользователи неизвестны user-embedding reward model: используется прежний fallback, без адаптации. Это другая популяция оценки; её абсолютные метрики нельзя напрямую сравнивать с прежним test как измерение прироста. Сравнение политик выполняется попарно внутри новой выборки.

## Итоговое сравнение

После записи окончательного выбора и SHA checkpoint открывается новый holdout. Оцениваются baseline, фиксированные rl-only, strong-kl и next-item-only seed 42, выбранный смешанный checkpoint seed 42, если он подтверждён, а также популярность и недавние треки. Если смешанный вариант не принят, основной вывод - гипотеза не прошла правила; контроли оцениваются по тому же плану. По holdout модели заново не выбираются.

Основное подтверждение для смешанного кандидата против baseline требует одновременно:

1. Нижняя граница 95%-го user-cluster интервала разницы hybrid top-10 reward > 0.
2. Нижняя граница интервала разницы NDCG@10 >= -1% NDCG baseline на этом holdout.

Это заранее заданный тест не меньшего качества с допуском, а не вывод из включения нуля в интервал. Дополнительные сравнения с next-item-only и strong-kl описательные. Bootstrap: 2 000 повторов, seed 42, равный вес запросов. Число seeds не устраняет адаптивность старой validation или неопределённость reward model.

Фактические доли присоединяются только после фиксации выбора по прежнему правилу дубликатов и clipping. Reward model оценивается на наблюдавшихся парах без обучения; метрики совпадений списков сопровождаются покрытием и не объявляются несмещённой оценкой отклика политики. Рост прогноза не доказывает удовлетворённость или удержание.
