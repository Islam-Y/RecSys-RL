# Подбор настроек маленькой GPT-2

Зафиксировано 2026-10-14 до запуска серии. Архитектура 2 слоя / размер 128 / 4 головы выбрана по предыдущим сравнениям размеров. Цель — проверить настройки обучения и устойчивость найденного изменения. План: [small-tuning.json](../configs/small-tuning.json).

## Данные и модель

Повторно используются прежние `data/processed/mvp/`: 59 888 train-запросов, 5 000 validation, каталог 2 000 треков, история до 64 событий. Правила времени, нескольких целей на timestamp и ранжирования полного ограниченного каталога сохраняются. Исходные данные, подготовленные массивы и каталог не пересоздаются. Финальный test не оценивается, проверяется только SHA-256.

GPT-2 обучается с нуля. Архитектура и число параметров сохраняются: 661 504. Seed подготовки данных остаётся 42. Новый `training.seed` меняет только инициализацию модели, dropout и перестановку обучающих запросов; значения 43 и 44 не меняют состав пользователей, запросов или каталог. Для старых конфигураций без `training.seed` используется прежний seed.

## Этап 1: восемь рецептов, training seed 42

| Рецепт | Learning rate | Dropout | Weight decay |
|---|---:|---:|---:|
| control | 0.0005 | 0.10 | 0.01 |
| lr-low | 0.0001 | 0.10 | 0.01 |
| lr-medium | 0.0003 | 0.10 | 0.01 |
| lr-high | 0.001 | 0.10 | 0.01 |
| dropout-low | 0.0005 | 0.05 | 0.01 |
| dropout-high | 0.0005 | 0.20 | 0.01 |
| decay-low | 0.0005 | 0.10 | 0.001 |
| decay-high | 0.0005 | 0.10 | 0.1 |

Относительно контроля каждый рецепт меняет один параметр. Dropout одновременно применяется к embeddings, attention и residual-частям, как в исходной реализации. Сочетания изменений не перебираются; результат не является глобальным оптимумом.

У всех рецептов максимум 30 эпох, early stopping после пяти последовательных эпох без строго большего validation NDCG@10. Выбирается checkpoint с наибольшим NDCG@10, при равенстве — более ранний. AdamW, batch 128 и gradient clip 1.0 сохраняются. Learning rate постоянный; warmup и scheduler не добавляются.

Контроль также запускается с новым бюджетом. Разница его результата с прежними 15 эпохами описывает эффект изменения бюджета. Сравнение кандидатов с новым контролем описывает эффект настройки при общем максимуме эпох и правиле остановки. Фактические эпохи и вычислительные затраты могут различаться.

## Этап 2: парное сравнение на трёх training seeds

По результатам seed 42 выбирается лучший рецепт среди семи вариантов без `control`, по NDCG@10. При равенстве выигрывает более ранний в таблице. Также фиксируется победитель среди всех восьми, который может оказаться контролем.

Выбранный кандидат и контроль сравниваются на seeds 42, 43 и 44. Запуски seed 42 повторно используются; дополнительно выполняются четыре обучения: контроль и кандидат с seeds 43 и 44. Остальные настройки и данные сохраняются. Максимум серии — 12 отдельных обучений.

Фиксируются все шесть Recall/NDCG @5/10/20, среднее и выборочное стандартное отклонение по трём seeds, парные абсолютные и относительные изменения. Диагностики охвата, концентрации, повторов и длительности сохраняются для каждого checkpoint.

**Правило выбора для следующего этапа:** кандидат заменяет контроль, только если его NDCG@10 строго выше на каждом из трёх парных seeds. Иначе сохраняется исходный рецепт с новым бюджетом. Это консервативное правило выбора, не проверка статистической значимости. В качестве исходного checkpoint выбранного рецепта используется seed 42; лучший seed по validation отдельно не выбирается.

## Ограничения

Архитектуры и рецепты последовательно выбираются на одной validation. Повторы меняют случайность обучения, но не дают независимую выборку пользователей или временной период. Стандартное отклонение по трём seeds не является доверительным интервалом. Прирост на validation может быть оптимистичным; финальный test остаётся для итоговой оценки после фиксации эксперимента с RL.

Оценка условна на популярном подкаталоге; потеря истории через UNK сохраняется. Офлайн-метрики и диагностики не измеряют удовлетворённость или причинный эффект на возвращаемость. Reward model и RL в эту серию не входят. Сильный контроль по недавним трекам сохраняется.

## Исполнение и воспроизведение

```bash
python -m recsys_rl tune --device auto
```

Каждое обучение выполняется в отдельном процессе. В `outputs/small-tuning-v1/` сохраняются план с хешами кода/конфигураций/данных, конфигурация каждого запуска, checkpoint, ranking-списки, история, лог и запись сверки. На macOS `/usr/bin/time -l` измеряет полный дочерний процесс; учёт памяти процесса не равен полному пику MPS или системы. Перед зачётом результата метрики пересчитываются по сохранённым рекомендациям, проверяются контроли и хеши.

Непустой каталог не перезаписывается. Для продолжения той же серии:

```bash
python -m recsys_rl tune --device auto --resume
```

Повторно используются только завершённые записи после сверки; код, данные, план и протокол должны совпадать. Незавершённый запуск с непустым каталогом нужно сохранить отдельно перед повтором: состояния оптимизатора для продолжения внутри эпохи нет.

Итог — `outputs/small-tuning-v1/result.json`. После сверки агрегированный отчёт копируется в `experiments/small-tuning-result.json`. Сырые данные и веса остаются локальными.
