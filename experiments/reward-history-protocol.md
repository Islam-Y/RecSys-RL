# Контроль смеси и усиление reward model: протокол до запуска

15 октября 2026. Продолжение после recency-v1; прежние три оценочные популяции открыты.

## 1. Проверка источника прироста

При tau = 16 сравниваем исходную GPT-2, выбранную обученную долю 0.1080394, фиксированные 0.10 и sigmoid(-2) = 0.1192029. Только прежние validation и открытая recency-популяция: это диагностическое, заранее не независимое сравнение. Считаем NDCG/Recall и парные интервалы, без объявления эквивалентности по включению нуля. Доли не подбираем. RL-reference остаётся прежняя выбранная смесь 0.1080394, даже если контроль окажется выше.

## 2. Reward model с наблюдавшейся историей откликов

Обучение на прежних 54 412 ранних наблюдавшихся парах; checkpoint по минимальному MSE прежней поздней train-selection (14 039 пар). Не меняем каталог, целевые метки и временные границы. Случайные кандидаты не получают меток нулевого отклика.

К каждой истории добавляем played_ratio только строго прошлых listen-событий, максимум 64 события. Дубликаты одного прошлого user/T/item предварительно усредняются для истории откликов; это не меняет историю ID GPT-2. Отсечение строго T'<T, включая все текущие цели. Неполные/отсутствующие доли не считаются нулями. Признаки пользователя: сглаженная средняя, короткие средние, разброс, доля дослушиваний/нулей, заполненность истории. Признаки кандидата: число/давность появлений, сглаженная средняя его прошлых долей, длительность, средняя по треку из раннего reward train. Для train item mean применяется leave-one-out по текущей наблюдавшейся паре. Для последующих периодов prior содержит только ранний train.

Персональный prior рассчитывается из доступных прошлых откликов, не user ID. Базовый прогноз для всех моделей — среднее logits сглаженных item/user priors. Три рецепта: линейная поправка по 16 числовым признакам; MLP по тем же признакам и embeddings истории/кандидата; тот же MLP с 0.05 * pairwise logistic loss по наблюдавшимся в одном user/T кандидатам с разными метками. Pair loss использует разность logits и знак разности долей; все подходящие пары, отдельный случайный batch 128 на каждом MSE batch. Ни один сэмплированный неслушавшийся объект не размечается.

Seed 42, AdamW lr 0.001, wd 0.01, batch 256, clip 1, максимум 12 эпох, patience 4. Лучший selection MSE; равенство — ранняя эпоха. Всего три обучения, без расширения после результатов. MLP: embedding 16, GELU 64→32, dropout 0.1; последняя поправка нулевая при инициализации. Линейная поправка также нулевая.

Контроли: общий prior; сглаженный item prior; средняя прошлых откликов пользователя; их logit-смесь; средняя прошлого отклика пользователя на кандидата; исходная raw/hybrid reward model. Сравнение с сильными контролями обязательно. Past-response признаки — расширение состава наблюдаемой истории; прирост нельзя приписывать только архитектуре.

## 3. Новые пользователи и выбор reward model

До обучения выделяем reward-development: 500 ранее не использованных пользователей по минимуму 50 ранних listen, hash(uid,20261017), исключая полные три прежние популяции (3 000). До 5 000 запросов из validation-периода. Отдельно выделяем final reserve: 1 000 пользователей, hash(uid,20261018), исключая также все 500 development-пользователей; до 5 000 запросов test-периода. Обе группы и ID-контексты/SHA фиксируются до запусков. При выделении response не читается. Final reserve не открываем для прогнозов/response, пока не записано окончательное решение следующей RL-серии.

Новая development-группа используется для выбора рецепта, поэтому не является final test. После фиксации трёх checkpoint открываются её метки/строго прошлые отклики. Условия допуска reward model к RL:

- MSE на новых development-пользователях ниже исходных raw и hybrid, общего prior и персональной средней прошлых откликов;
- query-macro pair accuracy для разрыва меток >= 0.10 минимум 55%, не ниже сглаженного item prior;
- минимум 100 запросов с такими парами;
- MSE на прежней selection не выше лучшего из исходной raw/hybrid и персональной средней прошлых откликов более чем на 1%.

Среди допустимых выбирается минимальный новый development MSE. Это рабочий порог сигнала, не статистическое доказательство полезности reward. Интервалы, веса пар/запросов и объём поддержки публикуются. Если никто не проходит, новая RL-серия не запускается, final reserve остаётся закрытым. Порог после результата не ослабляется.

## 4. Условная следующая RL-серия

При прохождении reward gate отдельный код/протокол фиксируются до RL-запусков. Reference — замороженная выбранная recency-смесь. Ограниченный бюджет: четыре рецепта seed 42 (KL 0.1/1, каждый без/со штрафом повтора последнего объекта), пять эпох, максимум два подтверждающих seeds выбранного рецепта. Reward model фиксируется. Предпочтение повторного знакомого трека само по себе не штрафуется; штраф касается соседнего повторения. Простое декодирование с запретом соседнего повтора — контроль. Многошаговые синтетические переходы не выдаются за реальные пользовательские действия.

До RL фиксируются точная цель/коэффициент штрафа, критерии релевантности/reward/повторов и правило открытия final reserve. До этого этапа финальные метки не читаются. Если reward gate не пройден, этой серией проверены механизм смеси и качество сигнала; улучшение RL не заявляется.
