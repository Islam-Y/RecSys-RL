# Протокол итоговой оценки - 2026-10-14

Записан до чтения содержимого test и присоединения его response-меток. Выбор RL завершён на validation; исходный результат - коммит `dc944dccc938dd7a53094f7e60fb2665703f126f`. Настройки, веса, каталог и калибровка фиксируются по хешам. После открытия test новых обучений и выбора победителя по нему не выполняется.

## Сравнения

Основное парное сравнение: выбранный **raw-kl, beta = 0.1, seed 42, эпоха 5** против исходной GPT-2 seed 42, эпоха 26. Checkpoint выбран по правилу пилота и подтверждён seeds 43/44. Другие seeds baseline или RL на test не перебираются.

Дополнительное заранее заданное сравнение: **raw-strong-kl, beta = 1, seed 42, эпоха 5**. Оно показывает более осторожную регуляризацию и не заменяет выбранную основную политику. Контроли: train-популярность и недавние треки с заполнением популярными. Другие пилотные варианты на test не оцениваются.

Оцениваются все 5 000 уже подготовленных test-запросов с 5 793 целями и 755 пользователями; эти количества известны из manifest. Каталог - прежние 2 000 объектов, история - BOS и последние 64 события строго раньше T. Границы: `23121935 < T <= 26000000` секунд. Повторные прослушивания допустимы. Цели одного timestamp оцениваются множеством, текущие события отсутствуют в истории. Ранжируется весь каталог, негативы не сэмплируются.

## Метрики

- Основная метрика: NDCG@10. Дополнительно Recall/NDCG @5/10/20, охват, концентрация десяти самых выдаваемых объектов, повторы, длительность и прежние разрезы.
- Общие raw/hybrid/time reward top-10 с равными весами позиций. Калибровка, пользовательская средняя и D95 = 285 секунд не подбираются заново.
- Отдельно ожидаемый reward полной softmax-политики, KL к reference, энтропия, масса объектов с поддержкой <= 10 ранних reward train пар.
- Парные разницы NDCG@10, Recall@10 и hybrid reward: percentile bootstrap пользователей, 2 000 повторов, seed 42; запросы внутри выборки имеют одинаковый вес. Интервалы вторичных сравнений описательные, без коррекции множественных проверок.

Основной результат описывается независимо от знака эффекта. Порог сохранения 95% NDCG из validation не используется для повторного выбора по test. Интервал, включающий ноль, не доказывает эквивалентность. Test отделён по времени, но использует прежних пользователей и ограниченный каталог; это не независимая популяция новых пользователей.

## Reward model и фактические метки

Фактические доли test-треков присоединяются из исходного Yambda по `(user, T, item)` прежней функцией: среднее `min(played_ratio_pct, 100)/100`, нули сохраняются, отсутствующие метки исключаются. Непрослушанные кандидаты не получают нулевых меток.

Frozen reward model, её фиксированные calibrated/hybrid преобразования и global/item/user mean из раннего reward train оцениваются на одинаковых наблюдавшихся test-парах по MSE/MAE, калибровке и разрезам. Попарное различение на одинаковом user/T/истории повторяет протокол reward-signal, включая разрыв меток >= 0.10. Никаких коэффициентов по test не оценивается.

Статистика дослушивания на совпадениях рекомендованного списка с наблюдавшимися треками сопровождается покрытием. Это условная статистика, не контрфактический отклик и не несмещённая оценка ценности политики. Высокий прогноз reward не является доказательством удовлетворённости или удержания.

## Выполнение и аудит

Код, этот протокол и конфигурация коммитятся до запуска. До `load_partition(..., "test")` записывается план с хешами и временем открытия. Сохраняются test-пары, reward полного каталога, logits трёх политик, ranking контролей и отчёт. Непустой каталог результата не перезаписывается. Аудит повторяет forward сохранённых весов и метрики на тех же данных; это пересчёт фиксированной оценки, а не новый эксперимент или подбор.

```bash
python -m recsys_rl.final_evaluation --device auto
python -m recsys_rl.final_evaluation --device auto --audit
```

Время и память измеряются для полного процесса через `/usr/bin/time -l`. Синтетические rollout остаются результатом предыдущего validation-пилота; новые реальные отклики им не приписываются. Результат test, пределы одношагового метода и идеи для долгосрочных целей включаются в итоговый Markdown/PDF.
